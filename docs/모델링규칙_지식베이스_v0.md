# 3D 모델링 규칙 지식베이스 v0

원산안면대교(솔빛대교) 사장교·접속교 3D 모델링 프로젝트에서 실전으로 확립한 규칙의
정본이다. 본 서비스(도면+사진 → AI 에이전트 3D 모델링)의 에이전트 프롬프트·검증기·
질문 UI가 이 규칙을 구현한다. 원 출처: `D:\Projects\Inspection\mbi_app_v2\docs\지식베이스_교훈.md`
(실수·교훈 83항), 같은 repo의 `models_3d/ab1/SPEC_v2.md`·`접속1교_실측정리.md`(방법론 실례).

## 1. 좌표·단위 규약

- 프로젝트마다 **전역 좌표계를 최우선 확정**하고 문서 최상단에 명시한다.
  (예: x=교축직각(+동측), y=EL−오프셋, z=STA−오프셋, Y-up, 단위 m)
- 도면 치수는 mm 정본, 모델은 m — 변환은 한 곳(빌더 상수)에서만.
- 기준선(받침선·매치라인·STA)과 모델 원점의 대응표를 SSOT 문서에 둔다.
- 방위(동/서 등)가 미확정이면 **가정임을 표기**하고 뒤집기 검증 항목으로 등재한다.

## 2. 치수 정본(SSOT) — "실측정리" 문서

- 모델링 착수 전 **치수 정본 문서**를 만든다. 모든 수치에 근거 도면번호를 병기한다.
- **확정 / 추정 / 미결을 분리**한다. 추정을 확정처럼 쓰는 순간 사고가 난다.
- 파생 계산(z 환산, 좌표 유도)은 원문값과 구분 표기하고 **검산을 동반**한다
  (구간 합=전장, 간격×개수=연장, 포물선 A×L²=낙차 등 — 검산 없는 수치는 싣지 않는다).
- 문서는 버전을 올리며 정정 이력을 남긴다(v1.1 → v1.1.x). 사용자 정정은 즉시 반영하고
  정정 사유를 기록한다.

## 3. 도면 판독 프로세스

- **표제란 전수 대조 먼저**: 파일명·폴더명은 내용을 보장하지 않는다(편철 오류 실례 있음).
  도면번호를 시트 내부 텍스트와 기계 대조한 뒤 불일치만 사람이 본다.
- 텍스트 추출(sheet_text)과 이미지 판독을 **병용**한다. 치수는 사슬(체인) 단위로 읽고
  합계 검산으로 확정한다.
- **단일 소스 판독 금지**: 중요 치수는 2개 이상 뷰·시트에서 교차 확인한다.
  (단면도 vs 상세도 vs 일반도 — 서로 다른 존을 본 것일 수 있다: "3열 vs 8열"류 상충의
  정답이 '구간별 병존'인 사례)
- 시트 하단 **요약도(키플랜)의 해치**로 커버 구간을 확정한다. 요약도 라벨이 본문에
  오탐되므로 본문 좌표의 표기만 근거로 쓴다.
- 판독 에이전트는 **애매한 값을 절대 추정으로 확정하지 않는다**. ambiguity로 분리한다:
  `{항목, 시트, 크롭 픽셀박스, 해석 선택지 2~4(각 근거), 모델 영향}` — 이 구조가
  사용자 질문 카드의 원천이다.
- 산출된 SSOT는 **적대적 검토**(별도 에이전트, 반박 시도)를 거친다. FAIL 지적은 원문
  재현으로 재확인한 뒤에만 수용한다.

## 4. 사용자 질문 프로토콜 (서비스 핵심 UX)

- **한 질문 = 한 요소.** 여러 애매점을 한 질문에 묶지 않는다.
- 질문에는 반드시 **해당 도면의 크롭 이미지**를 동반한다(원본 픽셀 좌표에서 잘라
  확대, 필요 시 두 시트 대조 크롭).
- 선택지 형식: 각 선택지에 근거를 붙이고, **권장안을 첫 번째**에 두며, 선택에 따라
  **모델이 어떻게 달라지는지(모델 영향)**를 명시한다.
- "모르겠다 — 권장대로 진행, 나중에 확인" 선택지를 항상 허용하고, 그 결정은
  SSOT에 **잠정**으로 기록해 미결 목록과 연동한다.
- 답변이 다른 판독과 모순되면 즉시 재질문하지 말고 근거를 갖춰 1회 재확인한다.

## 5. 모델링 규칙

- **부재 = 독립 노드.** 명명 규칙을 정하고 전 부재에 일관 적용한다
  (예: `AB1_S5_DIA07`, `AB1_S5_WG097L`). 노드명이 곧 객체 DB·망도 연결 키다.
- 스윕은 **외면 기준**, 판두께는 내면 방향(외면 평탄 관례). 두께 변화는 분절 스윕.
- 반복 부재는 **존(zone) 모델**로: 구간별 배열 규칙(간격·열수·규격)을 데이터로 두고
  빌더가 전개한다. 전이 구간 처리는 유력안 채택 + 주석.
- **단순화는 숨기지 않는다**: 빌더 헤더에 [A1]~[An] 번호로 전 항목 명기(사유 포함).
  사양과 모순 발견 시 임의 재해석하지 않고 사양대로 두되 모순을 보고한다.
- 메시는 수밀(watertight)을 기본으로 하고 빌더가 자체 검사한다.
- **세그먼트 단위 진행 + 승인 게이트**: 대표 구간 시범 → 사용자 승인 → 확산.
  내부(격실·보강재)까지 모델링하는 것이 기본이다.
- **보강재 방향 규약**: 판 보강재는 두께 t 를 판면 안 방향(격벽이면 x), 돌출 w 를 판면 법선
  방향(격벽이면 z)으로 판면에서 뻗는다. 판 두께는 스펙값 그대로 두고, 보강재는 별도 솔리드로
  판면에 INS 만큼 물려 같은 노드에 합친다.
- **편측 부착 단순화**: 지점 격벽의 수직·잭업보강재는 경간 안쪽 면에만, 일반 격벽의 개구보강재는
  +z 면에만 둔다(참조 빌더 [A4]·[A5]). 노드 bbox 는 판+보강재 전체 범위다.

## 6. 검증 규칙 (3중)

1. **빌더 self-check**: 그리드 검산(간격×개수), 부재 개수, 기준 EL/좌표 대조,
   수밀 검사 — 실행 출력으로 PASS/FAIL을 남긴다.
2. **독립 재실측**: 빌더를 신뢰하지 않는 별도 에이전트가 산출물(GLB)을 처음부터
   다시 열어 측정한다. 기대값은 빌더 코드가 아니라 **사양서에서 자체 유도**.
   허용오차 명시(예: 치수 5mm, 개수 0). bbox 중심이 아닌 실면 슬라이스로 측정
   (보강재 편측 부착이 bbox를 왜곡시킨 실례).
3. **렌더 육안**: 실척 정사영(set_aspect equal), 맥락 렌더(인접 구간 스텁·지지 조건
   포함 — 경간만 뚝 자른 렌더는 형상 오해를 부른다), 내부 컷. 렌더 검수 없이
   "완료"라고 말하지 않는다.

- 검증 없이 완료 주장 금지. 실패는 실패로 보고(출력 포함).
- 실물 사진·영상이 있으면 도면×실물 2단 판정. 실물로 확인 못 한 것은 "미확인"으로.

## 7. 문서·산출물 체계

- `SPEC.md`(사양 정본): 사용자 결정(확정/잠정 구분)·좌표계·부재별 치수·산출물 정의.
  모델과 1:1로 유지하고, 모델 승인 후 SSOT에 역반영한다.
- 산출물: GLB + 빌더 코드 + 재실측 JSON + 렌더 세트. 전부 버전 관리.
- 2D 연동을 전제로 **뷰 계약**(origin + u·extent·u_axis + v·extent·v_axis, 왕복 검산)
  을 함께 산출하면 시트·웹뷰어와 좌표 호환된다.

## 8. 오케스트레이션 패턴 (에이전트 운영)

- 판독·모델링·검증은 **서로 다른 에이전트**가 맡는다(자기 검증 금지).
- 병렬화 단위: 판독=도면 영역(계열)별, 모델링=부재 그룹별, 검증=관점별(수치/구조/논리).
- 에이전트 출력은 스키마 강제(구조화 출력) — 근거(도면번호·좌표) 없는 수치는 반려.
- 작업 순서: 표제란 대조 → 병렬 판독 → SSOT+검토 → 질문 루프 → 시범 모델 →
  3중 검증 → 승인 게이트 → 확산. 각 단계 산출물이 다음 단계의 유일한 입력이다.
