# 샘플 도면 세트

## 왜 파일이 여기 없는가

참조 원본(`CLAUDE.md` §2)은 **사용자 로컬에만 있고 읽기 전용**이다. 도면 PDF·DWG 는
용량이 커서 커밋할 수 없다. 그래서 이 디렉터리에는 **무엇이 있어야 하는가**만 둔다.

| 파일 | 커밋 | 내용 |
| --- | --- | --- |
| `<set_id>/set.json` | O | 세트 정의 — 설명, 원본 위치 힌트, **정답 글롭**, 제외 글롭 |
| `<set_id>/manifest.json` | O | 경로·크기·SHA256·역할·분류 근거·정답 봉인 |
| 실제 도면 파일 | X | `work/samples/<set_id>/` (`.gitignore` 대상) |
| 원본 경로 | X | `.env` 의 `M3D_SAMPLE_SOURCE_<SET_ID>` (사용자마다 다름) |

매니페스트가 커밋되므로 **원본이 없는 환경(클라우드 컨테이너, CI)에서도** 세트 구성을
알 수 있고, 나중에 무결성을 대조할 수 있다.

## 디렉터리 레이아웃

```
samples/<set_id>/set.json          커밋 — 세트 정의
samples/<set_id>/manifest.json     커밋 — 무엇이 있어야 하는가

work/samples/<set_id>/source/      판독 파이프라인 입력 (도면·사진·문서)
work/samples/<set_id>/answers/     M3 대조 기준(정답) — 입력과 물리적으로 분리
```

## 연결 방법 (원본이 있는 머신에서)

1. 리포 루트에 `.env` 를 만든다 (`.env.example` 참고).

   ```dotenv
   M3D_SAMPLE_SOURCE_AB1_P4P5=D:\Projects\Inspection\mbi_app_v2\assets\drawings_organized\_정밀조사패키지_P4P5
   ```

   환경변수 이름은 `M3D_SAMPLE_SOURCE_` + 세트 id 를 대문자로 바꾸고 `-` 를 `_` 로 바꾼 것이다.

   > ⚠ **Windows 경로를 큰따옴표로 감싸지 말 것.** dotenv 는 큰따옴표 안의 백슬래시를
   > 이스케이프로 해석한다. `"D:\Projects\new\test"` 는 `D:\Projects`+개행+`ew`+탭+`est`
   > 가 된다 (실측 확인). 따옴표 없이 쓰거나 작은따옴표를 쓴다. 슬래시(`D:/...`)도 된다.
   > 공백·한글이 든 경로도 따옴표 없이 그대로 쓴다.

2. 원본을 작업 디렉터리로 가져온다. **원본에는 쓰지 않는다** — 읽고 복사만 한다.

   ```bash
   uv run --project apps/worker m3d samples ingest ab1_p4p5 --dry-run   # 계획만 확인
   uv run --project apps/worker m3d samples ingest ab1_p4p5
   ```

3. 생성된 `samples/ab1_p4p5/manifest.json` 을 커밋한다.

## 명령

| 명령 | 하는 일 |
| --- | --- |
| `m3d samples list` | 등록된 세트와 매니페스트 상태 |
| `m3d samples status` | 세트별 원본·매니페스트·로컬 파일 유무 |
| `m3d samples ingest <id>` | 원본 → 작업 디렉터리 복사 + 매니페스트 갱신 |
| `m3d samples verify <id>` | 매니페스트 ↔ 실제 파일 대조 |
| `m3d samples paths <id>` | 파이프라인이 쓸 입력 루트 (`--answers` 로 정답 루트) |

`ingest` 옵션: `--dry-run` (복사 안 함) · `--prune` (원본에서 사라진 파일 정리) ·
`--recheck` (해시로 재대조) · `--force` (전부 다시 복사).

## 원본이 없는 환경에서는 (이 클라우드 컨테이너, CI)

`verify` 는 세 상태를 **구분해서** 보고한다.

| 상태 | 뜻 | 종료코드 |
| --- | --- | --- |
| `OK` | 파일이 있고 매니페스트와 일치 | 0 |
| `ABSENT` | 매니페스트는 있는데 이 머신에 파일이 없음 | 0 (`--require-files` 면 3) |
| `MISMATCH` | 파일이 있는데 다름 — 누락·변조·초과 | 1 |

`ABSENT` 를 오류로 만들면 원본 없는 CI 가 영구히 빨간불이 되어 아무도 안 보게 된다.
그렇다고 조용히 성공시키면 "검증했다"는 거짓 보고가 된다 (규칙 §8). 그래서 **성공시키되
상태를 명시**하고, 파일이 반드시 있어야 하는 단계는 `--require-files` 로 막는다.

Windows 경로를 리눅스에서 만나면 "디렉터리가 아닙니다" 대신 **왜 그런지**를 말한다 —
Windows 경로임을 알아채고, WSL 경로를 제안하고, 매니페스트만으로 할 수 있는 일을 안내한다.

## 정답 데이터 취급 — 별도로 취급한다

`SPEC_v2.md`, 재실측 JSON 은 **M3 대조 기준**이다 (아키텍처 §5 — v0 합격 기준).
판독 파이프라인이 이것을 보면 채점 대상이 채점표를 보고 답을 쓰는 셈이 된다. 그래서:

1. **선언으로만 정해진다.** `set.json` 의 `answers` 글롭에 명시된 것만 정답이 된다.
   파일명 추측(`"spec" 이 들어갔으니 정답이겠지`)은 쓰지 않는다 — 오분류 한 번에
   정답이 입력으로 새거나 진짜 도면이 입력에서 빠진다 (규칙 §3).
   계약이 이를 강제한다: `role=answer` 인데 `role_source≠declared` 면 매니페스트가 거부된다.
2. **물리적으로 분리된다.** 정답은 `answers/`, 나머지는 `source/`. 판독 에이전트에게는
   `m3d samples paths <id>` (= `source/`)만 준다. 정답 경로는 `--answers` 를 **명시**해야 나온다.
3. **봉인된다.** `manifest.answers_seal` 은 정답 파일 집합의 SHA256 이다. 정답을 고쳐
   M3 대조를 통과시키면 봉인이 깨지고 `verify` 가 잡아낸다 (규칙 §6·§8).
4. **의심스러우면 묻는다.** 정답처럼 보이는데 선언되지 않은 파일은 `ingest` 가 경고로
   보고하고 **자동 분류하지 않는다**.

## 한글 파일명 / 경로 정책

매니페스트 경로는 항상 **POSIX 구분자 + 유니코드 NFC** 로 기록한다. 이유는 실측된 함정들이다.

- **NFD 파일은 NFC 이름으로 열리지 않는다.** 리눅스 파일명은 불투명 바이트라 정규화를
  하지 않는다. macOS(HFS+)가 만든 NFD 이름의 파일을 리눅스로 가져오면
  `Path(NFC이름).exists()` 가 **False** 다. → 매니페스트의 `path` 는 **식별자이지
  열 수 있는 경로가 아니다.** 실제 접근은 스캔이 돌려준 `Path` 객체로만 한다.
- **NFC 정규화는 충돌할 수 있다.** NFC 이름과 NFD 이름이 한 디렉터리에 공존할 수 있고
  (리눅스에서 실측), 정규화하면 같아진다. 그대로 복사하면 한쪽이 조용히 사라지므로
  **탐지해 거부**한다.
- **cp949 로 깨진 파일명은 매니페스트를 쓸 수 없다.** Windows zip 을 유니코드 미인식
  도구로 풀면 파일명이 유효한 UTF-8 이 아니게 되고, UTF-8 JSON 으로 쓸 때
  `UnicodeEncodeError` 가 난다. → 스캔 시점에 무엇이 왜 문제인지, 어떻게 고치는지
  한국어로 말하고 멈춘다.
